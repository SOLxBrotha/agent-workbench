# Contributing

Open an issue describing the user outcome before proposing a workflow change. Keep one capability per pull request and identify its base commit.

Every pull request must state:

- the behavior being changed;
- why the current text is insufficient;
- every changed file;
- the checks and direct usage proof;
- any security or authority change;
- the rollback or revert path.

Do not include secrets, private repository content, generated transcripts, internal handoffs, or copied third-party skill text. Research claims must cite primary sources. Run the repository checks documented in the current PRD before requesting review.
